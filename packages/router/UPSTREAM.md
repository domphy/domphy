# @domphy/router — Upstream

`@domphy/router` is a 1-1 port of [**@tanstack/router-core**](https://github.com/TanStack/router/tree/main/packages/router-core) (MIT-licensed) plus a thin in-house Domphy adapter (`src/domphy/`, shipping from the main entry). This file records the pinned upstream version, the port's scope, every intentional deviation from upstream, and the re-sync procedure.

## Upstream version

**Pinned: `@tanstack/router-core@1.171.32`** (npm), re-synced 2026-09-23 from `1.171.13`. Every upstream-derived file under `src/` (everything except `src/domphy/`, `src/global.ts`, `src/vite-env.d.ts`) is the `1.171.32` file verbatim, with one mechanical rewrite applied port-wide: upstream's self-import `@tanstack/router-core/isServer` becomes `@domphy/router/isServer`.

Runtime dependencies are unchanged except `@tanstack/history`, bumped `^1.162.0` → `^1.162.4`: `1.171.32` imports `createServerHistory` and `normalizeProtocolRelative`, neither of which exists in `1.162.0`. Upstream moved `@tanstack/store` to a devDependency (nothing under its `src/` imports it); the port keeps it as a runtime dependency because the Domphy adapter (`src/domphy/stores.ts`) builds the client store factory from `@tanstack/store` atoms.

### What the re-sync brought over

`1.171.32` is a structural rewrite of the load pipeline, not a patch bump:

- `load-matches.ts` split into `load-client.ts` + `load-server.ts`. The client path is now a **transaction** model: `loadClientRoute` installs a `LoadTransaction` on `router._tx` with its own `AbortController`; a superseding load aborts its predecessor, and every commit, store write and redirect-follow is gated on `router._tx === tx`.
- `lru-cache.ts` replaced by `sieve-cache.ts` (the SIEVE eviction algorithm).
- New SSR modules: `htmlBoundaryScanner`, `hydrationScripts`, `renderSsrHtmlResponse`, `bodyScripts`, and six seroval plugin/codec files (`RawStreamJSONPlugin`, `RawStreamRPCPlugin`, `RawStreamSSRPlugin`, `makeSerovalPlugin`, `makeSsrSerovalPlugin`, `rawStreamCodec`, `seroval-plugins.ssr`).
- New `await-signal.ts`.

### Public API changes from the re-sync

Upstream removals that the port therefore no longer exports or exposes:

| Removed | Replacement |
|---|---|
| `RouterState.statusCode`, `RouterState.redirect` | `router._serverResult` — `{ type: 'redirect', redirect }` or `{ type: 'render', status, matches }`, set by a server-side `load()` |
| `router.hasNotFoundMatch()` | Inspect `match.status === 'notFound'` on `router.state.matches` |
| `router.getMatch(matchId)` | Removed upstream with the match-store rewrite |
| `router.stores.isLoading`, `router.stores.hasPending`, `router.stores.cachedMatches` | `router.stores.status` (`'pending' \| 'idle'`), `router.state.isLoading` |
| `resolvePath({ base, to, trailingSlash, cache })` | `resolvePath(base, to, trailingSlash?, cache?)` — positional, so the router's hot callers allocate no options object |
| `createLRUCache` (`src/lru-cache.ts`) | `createSieveCache` (`src/sieve-cache.ts`) |
| `MatchSupersededError`, `isMatchSupersededError` | Port-only sentinel, now obsolete — see "Deviations retired by the re-sync" |

`RouterCore.startTransition` also changed shape, which the Domphy adapter had to follow: it is now `(fn: () => void, expected: Array<AnyRouteMatch>) => Promise<boolean>`, and upstream emits the entire lifecycle (`onLoad`, `onBeforeRouteMount`, `onResolved`, `onRendered`) from `load-client.ts` itself. `onRendered` is emitted only when `startTransition` resolves `true`.

## Port scope

- Ported 1-1 from upstream: the entire headless core — route/route-tree definition, path matching/parsing (`path.ts`, `new-process-route-tree.ts`), history integration, `RouterCore` (`router.ts`), the match-loading pipeline (`load-client.ts` + `load-server.ts`), stores (`stores.ts`), redirects/not-found, SSR (`ssr/`), scroll restoration, search middleware, structural sharing, and all type machinery.
- In-house additions (no upstream counterpart): `src/domphy/` — the Domphy adapter (`createRouter`, `createRoute`, `createRootRoute`, `createRootRouteWithContext`, `createRouteMask`, `getRouteApi`) with a headless transitioner (`domphy/transitioner.ts`) replacing upstream's React `<Transitioner>`, `domphy/link.ts` (`linkProps`) — a headless port of `@tanstack/react-router`'s `useLinkProps` href/click logic (`getHrefOption` + `externalLink` + `handleClick`), returning plain props instead of a React `<Link>`, and `domphy/stores.ts` (`subscribeToRouterState`) — the headless equivalent of `useRouterState`; `@tanstack/history` re-export; `src/global.ts` (tsup global build shim).
- Not ported: upstream's framework adapters (React/Solid) — the Domphy adapter replaces them.

## Intentional deviations from upstream

| File | Deviation | Reason |
|---|---|---|
| `src/invariant.ts` + its 5 call sites (`new-process-route-tree.ts`, `route.ts`, `ssr/hydrationScripts.ts`, `ssr/ssr-server.ts` ×2) | `invariant()` takes an optional `code` and throws `Invariant failed (<code>)`. Call sites pass a stable slug (`'duplicate-route-id'`, `'missing-parent-route'`, `'hydration-already-committed'`, `'hydration-disabled'` / `'already-dehydrated'`, `'disable-hydration-after-dehydrate'`). | Upstream's production-path `invariant()` takes no arguments and throws the same `'Invariant failed'` string from every site, so a production bug report cannot be traced to a call site (the actionable message exists only behind the DEV `throw new Error(...)` above each call). The slug is a short stable code, not the full DEV message, so no message strings are shipped. Signature is backward compatible (`code` optional). Regression tests: `tests/invariant.test.ts`. |
| `src/redirect.ts` (`redirect()`) | A `Location` header that `isDangerousProtocol()` rejects is deleted from the incoming `opts.headers`, and a dangerous `opts.href` is never written to `Location`. | `redirect({ href: '//evil.com' })` otherwise produces a `Response` carrying `Location: //evil.com`. A server handler returns that `Response` as-is (`createRequestHandler` short-circuits with `return result.redirect`), so it is an open redirect; `javascript:` is the XSS variant. Upstream `1.171.32` still sets `Location` unconditionally. The check reuses upstream's own hardened `isDangerousProtocol` + `DEFAULT_PROTOCOL_ALLOWLIST`, so it adds no parallel parser. Regression tests: `tests/redirect.test.ts`, `tests/ssr-server.test.ts`. |
| `src/scroll-restoration.ts` + `src/router.ts` (`_scroll.ignoreScroll`, `_scrollRestorationCleanup`) / `src/domphy/router.ts` (`destroy()`) | The module-level `let ignoreScroll` becomes per-router `router._scroll.ignoreScroll`, and `setupScrollRestoration()` returns a cleanup function that removes every listener/subscription it registered. `history.scrollRestoration` is reset to `'auto'` only when the last active router tears down (module-level `activeScrollRestorations` refcount). `RouterCore` stores the cleanup on `_scrollRestorationCleanup`; the Domphy `Router.destroy()` invokes it. | Upstream's React adapter has no router teardown path, so `setupScrollRestoration` never unwires — the `document` scroll listener, `pagehide` listener and two router subscriptions leak for the lifetime of the page, and the module-level `ignoreScroll` is shared across every router instance (one router's restore pass suppresses another's scroll tracking). Domphy apps discard routers on HMR and locale switches, so the port needs a real teardown. Regression tests: `tests/scroll-restoration.test.ts` (listener/subscription removal on destroy, snapshotting stops after destroy, a surviving router keeps working when another is destroyed). |
| `src/router.ts` (~1823) | A commented-out upstream code block (the "I don't know if we should run the full search middleware chain" `accumulatedSearch` draft) is deleted. | Dead commented-out code; no behavior change. Listed here so the re-sync diff has no unexplained hunk. |
| `src/load-client.ts` (one comment) | A comment referring to the client SSR entry says `@domphy/router/ssr/client` instead of `@tanstack/router-core/ssr/client`. | Comment-only; names the subpath this package actually publishes. |
| `src/domphy/link.ts` (`linkProps`) vs `@tanstack/react-router@1.170.38` `src/link.tsx` (`useLinkProps`) | Ports only the parts of `useLinkProps` that are pure functions of the router + options: `resolveExternalLink`, `getHrefOption`, `handleClick`'s guard chain (`disabled`, modifier keys, `defaultPrevented`, effective `target`, `button === 0`) and the `linkDisabled` half of `applyLinkState` (`role="link"` + `aria-disabled`, no `href`). **Not** ported: active-state computation (`isActive`, `activeProps`/`inactiveProps`, `data-status`/`aria-current`), preload on intent/viewport/render (`useIntersectionObserver`, the hover/focus timeout map), the class/style merging in `applyLinkState`, and the `isTransitioning` `data-transitioning` flag. Behavior on the ported surface is upstream's, including the blocked-protocol path. | Upstream's `<Link>` is a React component that can subscribe to the location store and own DOM refs/effects; `linkProps` is a one-shot props builder with no reactivity or element handle, so active state and observer-driven preloading have no place to live — a caller wires them with Domphy's own reactivity (see `apps/web/docs/router/navigation.md` "Active Links") and `router.preloadRoute()` on `onMouseEnter`. Class/style merging is React-prop shaping with no Domphy counterpart. Regression tests: `tests/link-props.test.ts`. |
| `src/domphy/stores.ts` (`subscribeToRouterState`) vs `@tanstack/react-router@1.170.38` `src/useRouterState.tsx` (`useRouterState`) | Exposes the store subscription as a plain `subscribeToRouterState(router, callback) => unsubscribe`. Ports upstream's server branch verbatim (`isServer ?? router.isServer` reads `__store` without subscribing). **Not** ported: `select` and `structuralSharing` (`useStructuralSharing`), and the `RouterReadableStore extends Readable` module augmentation. | Upstream's hook subscribes to `router.stores.__store` through `useSelector`; Domphy has no hook layer, so the subscription is handed to the caller, who mirrors it into a `State` with `toState`. Without it the store is unobservable from outside the package — `RouterReadableStore` declares only `get()` — and the `status: 'pending'` flip is invisible, since `onBeforeLoad` is emitted while the status is still `'idle'` and `onLoad` only after the loaders settle, so pending/spinner UI was unimplementable through the public API. `select`/structural sharing exist to skip React re-renders; a Domphy caller selects inside its own callback and `State.set` already drops `Object.is`-equal writes. The augmentation is omitted because it would poison the non-reactive server store factories compiled in this same package, so the cast is local. Regression tests: `tests/domphy-adapter.test.ts` ("publishes isLoading true while a loader runs, then false"). |
| `src/ssr/createRequestHandler.ts` | The `router.update({ history, origin })` call also passes `isServer: true`, and the handler throws a named error when the per-bundle `isServer` constant is `false`. | The handler installs a `createServerHistory` (whose `push()` is a no-op) and reads the load outcome off `router._serverResult`, which only `loadServerRoute` writes — so it already requires server mode, it just did not enforce it. A router left in client mode runs `followRedirect` → `commitLocation` → `load` forever on a redirecting route: the ignored `push()` never makes the target current, so upstream's 20-redirect cap (keyed on `router._pendingLocation.href`) never engages and the request never terminates — an unbounded loop, i.e. an OOM. Upstream never enforces it either, but never reaches the state: its own SSR tests always build server-mode routers, and in a Node/Deno/Bun/workerd process its `isServer` export condition resolves to `true`. The state *is* reachable wherever a `document` exists (jsdom test/SSR harness) or `isServer: true` is simply forgotten. `load()` dispatches on `isServer ?? router.isServer`, so the per-bundle constant outranks the option just set; when it is `false` (a server build that resolved the `browser` export condition) forcing cannot work, so the handler fails loud with a message naming the condition to fix instead of hanging. Regression test: `tests/ssr-server.test.ts` ("terminates on a redirecting route when the router was not created with isServer" — bounded by a 5s timeout; before the fix it starved the vitest worker past its own timeout and produced no output at all). |
| `src/domphy/router.ts` (`Router.load`) | The constructor wraps the base `load` so a destroyed router returns immediately. | `destroy()` must actually stop the router. `load` is an instance field (like `update`), so it is wrapped the same way. Without it an explicit `load()` — or a history event racing teardown — still runs the full core pipeline and emits the whole lifecycle. No upstream counterpart: `destroy()` is a port addition. Regression tests: `tests/transitioner.test.ts` ("emits no lifecycle events when load() is called on a destroyed router"). |
| `src/domphy/transitioner.ts` | Supplies `router.startTransition` (apply the commit, then resolve `true` after one macrotask, which is the headless equivalent of "the UI has committed"), subscribes `router.load` to history changes, and corrects the initial URL to its canonical form. `cleanup()` is idempotent and leaves `startTransition` inert (no commit, resolves `false`). Two things upstream's component does are **not** ported: the `router._rendered` acknowledgement array (`settleOwner`, the `expected` matches argument), and the initial-mount branch that either re-emits `onRendered` for an already-resolved location or calls `router.load({ sync: true })`. | Upstream's `<Transitioner>` is a React component. As of `1.171.32` the core emits the lifecycle itself and asks the adapter only for `startTransition`, so this module shrank to that plus the two jobs the component also did. Resolving `false` after cleanup is what stops a torn-down router from producing `onRendered`. `_rendered` is declared in core (`router.ts` ~1109) but read only by the React adapter (`Matches.tsx`), which settles it when React commits — there is no render commit to observe here, so the macrotask resolve replaces it. The initial-load branch is omitted because the adapter's documented contract is an explicit `await router.load()` at startup (`apps/web/docs/router/api.md`, `index.md`, `ssr.md`); emitting one here as well would load every app twice. `commitLocation` for the canonical correction passes `ignoreBlocker: true` as upstream does — normalizing the URL the app was opened at is not a user navigation, so a blocker must not veto it. Regression tests: `tests/domphy-adapter.test.ts`, `tests/transitioner.test.ts`. |

Port-added test coverage with no upstream counterpart: the RFC 3986 §5.2.4 root-clamp rows in `tests/path.test.ts`'s `resolvePath` table (`['/a', '../../b', '/b']` and friends — over-popping must not turn an absolute path into a relative one).

## Deviations retired by the re-sync

Each of these was a port fix for a defect upstream has since fixed itself. Per the re-sync procedure the port re-aligns rather than keeping a parallel mechanism.

| Retired deviation | Why it is obsolete |
|---|---|
| `RouterCore.load()` catch staleness gate (`loadLocation` identity check) | The client pipeline is now transaction-owned: `loadClientRoute` installs `router._tx` and every redirect-follow and commit is gated on `router._tx === tx` (`load-client.ts` ~1774, ~1823), with the superseding load aborting its predecessor's `AbortController`. Stronger than location identity. |
| `MatchSupersededError` / `getMatchOrThrow` sentinel | Same rewrite: stale continuations are aborted through the transaction's signal, not by dereferencing a deleted match store. The `getMatch(matchId)!` sites the sentinel guarded no longer exist. |
| `handleLoader` SWR background-redirect identity check | Same rewrite; `load-matches.ts` no longer exists. |
| `defaultGcTime` / `defaultPreloadGcTime` seeded to 30 minutes | Upstream re-aligned its JSDoc to its code: `RouterOptions` now documents `@default 300_000 (5 minutes)` and `load-client.ts` falls back to `300_000`. There is no longer a contract mismatch to correct. |
| `lru-cache.ts` `set()` existing-key-before-eviction reorder | `sieve-cache.ts` checks the existing key before the eviction branch already. |
| `resolvePath` `'..'` root clamp | Upstream clamps: `if (baseSegments.length > 1) pop() else baseSegments = ['']`. The port's extra table rows are kept as coverage. |
| `isDangerousProtocol` hardening (protocol-relative + scheme-like URL-ctor failures) | Upstream replaced the `new URL()` probe with `getUrlScheme()` (a WHATWG scheme-prefix regex) plus `protocolRelativePrefixRegex`, which also catches backslash and control-character variants (`/\evil.example`). Strictly stronger, so the port's version was deleted rather than kept. The related test ("treats scheme-like URL-ctor failures as dangerous") was removed: upstream classifies a malformed-but-scheme-bearing URL such as `http://[` by its scheme, which is correct. |
| `ssr/createRequestHandler.ts` `Location` sanitization before header merge | The code path is gone: `createRequestHandler` no longer merges `router.stores.redirect.headers` into the document response. A redirect short-circuits with `return result.redirect`, so `redirect()` is the single place to guard (see the deviation table). |
| `redirect.ts` duplicated one-line JSDoc | Fixed upstream. |

## Re-sync procedure

1. `npm pack @tanstack/router-core@<current-pin>` and `@<target>`; `diff -ru` the two `src/` trees. That upstream delta is exactly what to apply.
2. Replace every upstream-derived file under `src/` with the target version verbatim (excluding `src/domphy/`, `src/global.ts`, `src/vite-env.d.ts`), then re-apply the `@tanstack/router-core/isServer` → `@domphy/router/isServer` rewrite and each row of the deviation table above onto the new file layout. A deviation whose defect upstream has fixed moves to "Deviations retired by the re-sync" — re-align, never keep a parallel mechanism.
3. Upstream's own tests are the external truth for changed modules. Fetch them from `https://raw.githubusercontent.com/TanStack/router/@tanstack/router-core@<target>/packages/router-core/tests/<file>` (including `routerTestUtils.ts`) rather than hand-editing the port's copies, then re-add any port-only rows.
4. Diff upstream's `package.json` dependencies; adopt version bumps the new `src/` actually needs.
5. Bump the pin in this file and `CHANGELOG.md`, then run `pnpm --filter @domphy/router test`, `pnpm --filter @domphy/router build`, a real `tsc --noEmit`, and `pnpm --filter @domphy/app test` (app consumes the router).
